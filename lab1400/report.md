  - Топ-3 пользователей по сумме заказов с использованием CTE  
4. Создание индекса `idx_order_items_order_id` и сравнение плана выполнения (`Seq Scan` → `Index Scan`).  

### Ключевые фрагменты кода  

**Создание таблиц (`schema.sql`):**  
```sql
CREATE TABLE users (
    user_id SERIAL PRIMARY KEY,
    email VARCHAR(255) NOT NULL UNIQUE,
    full_name VARCHAR(255) NOT NULL,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
CREATE TABLE orders (
    order_id SERIAL PRIMARY KEY,
    user_id INTEGER REFERENCES users(user_id),
    order_date TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    status VARCHAR(50) DEFAULT 'pending'
);
```

**1 Запрос (итоговая сумма заказов):**  
```sql
SELECT 
    o.order_id,
    u.full_name,
    o.order_date,
    o.status,
    SUM(oi.quantity * oi.unit_price) AS total_amount
FROM orders o
JOIN users u ON o.user_id = u.user_id
JOIN order_items oi ON o.order_id = oi.order_id
GROUP BY o.order_id, u.full_name, o.order_date, o.status
ORDER BY total_amount DESC;
```

**2 Запрос (выручка по категориям):**  
```sql
SELECT 
    p.category,
    SUM(oi.quantity) AS total_sold,
    SUM(oi.quantity * oi.unit_price) AS total_revenue
FROM order_items oi
JOIN products p ON oi.product_id = p.product_id
GROUP BY p.category
HAVING SUM(oi.quantity * oi.unit_price) > 10000;
```

**3 Запрос (топ пользователей):**  
```sql
WITH user_totals AS (
    SELECT 
        u.user_id,
        u.full_name,
        SUM(oi.quantity * oi.unit_price) AS total_spent
    FROM users u
    JOIN orders o ON u.user_id = o.user_id
    JOIN order_items oi ON o.order_id = oi.order_id
    GROUP BY u.user_id, u.full_name
)
SELECT * FROM user_totals
ORDER BY total_spent DESC
LIMIT 3;
```

**Оптимизация при помози индекса:**  
```sql
CREATE INDEX idx_order_items_order_id ON order_items(order_id);
```

### Ключевые фрагменты кода

#### 1. Вставка заказа с вложенным массивом items
```javascript
db.orders.insertOne({
    _id: 1,
    user_id: 1,
    order_date: new Date("2026-04-15"),
    status: "completed",
    items: [
        { product_id: 1, quantity: 1, price: 75000 },
        { product_id: 2, quantity: 2, price: 1500 }
    ]
});
```

#### 2. Агрегационный пайплайн
```javascript
db.orders.aggregate([
    { $unwind: "$items" },
    { $lookup: {
        from: "products",
        localField: "items.product_id",
        foreignField: "_id",
        as: "product_info"
    }},
    { $unwind: "$product_info" },
    { $group: {
        _id: "$product_info.category",
        total_quantity: { $sum: "$items.quantity" },
        total_revenue: { $sum: { $multiply: ["$items.quantity", "$items.price"] } },
        avg_price: { $avg: "$items.price" }
    }},
    { $sort: { total_revenue: -1 } },
    { $project: {
        _id: 0,
        category: "$_id",
        total_quantity: 1,
        total_revenue: 1,
        avg_price: { $round: ["$avg_price", 2] }
    }}
])
```

#### 3. Топ 3 пользователей по сумме заказов
```javascript
db.orders.aggregate([
    { $unwind: "$items" },
    { $group: {
        _id: "$user_id",
        total_spent: { $sum: { $multiply: ["$items.quantity", "$items.price"] } }
    }},
    { $sort: { total_spent: -1 } },
    { $limit: 3 },
    { $lookup: {
        from: "users",
        localField: "_id",
        foreignField: "_id",
        as: "user"
    }},
    { $unwind: "$user" },
    { $project: { _id: 0, full_name: "$user.full_name", total_spent: 1 } }
])
```

## Ответы на контрольные вопросы  
**Часть 1:**
1. **В чём разница между `WHERE` и `HAVING` в агрегатных запросах?**  
   `WHERE` используется для фильтрации отдельных строк до группировки и агрегации данных. Он работает с исходными данными таблицы и не может использовать агрегатные функции, применяется к отдельным записям, а не к группам.
   `HAVING` применяется после группировки данных с `GROUP BY` и позволяет фильтровать группы строк по результатам агрегатных функций. Он работает с уже сгруппированными данными и может использовать агрегатные функции. 

2. **Зачем в запросе с `GROUP BY` нужно перечислять все неагрегированные столбцы?**  
    Перечисление всех неагрегированных столбцов в `GROUP BY` необходимо из-за стандартов SQL и требований к однозначности результатов. Согласно стандарту SQL, в списке `SELECT` могут присутствовать только те столбцы, которые: указаны в `GROUP BY` используются внутри агрегатных функций или являются константами.

3. **Как изменится результат `EXPLAIN ANALYZE` после добавления индекса? Что означает `Seq Scan` и `Index Scan`?**  
   - После создания индекса планировщик выбирает `Index Scan` вместо `Seq Scan` для условия `WHERE order_id = 1`.  
   - `Seq Scan` – последовательное чтение всей таблицы.  
   - `Index Scan` – поиск по индексу, при котором сначала находятся физические адреса нужных строк, затем считываются только они, что значительно быстрее при точечных запросах на больших таблицах.

**Часть 2:**
1. **Как в MongoDB представлена связь «заказ-товары» в отличие от PostgreSQL?**  
   В PostgreSQL используется отдельная таблица `order_items`, соединяемая через внешние ключи. В MongoDB товары хранятся в виде вложенного массива `items` внутри документа заказа, что позволяет получить все данные заказа одним чтением без `JOIN`.

2. **В каком случае документная модель удобнее реляционной? Приведите пример из работы.**  
   Документная модель удобнее реляционной, когда требуется гибкость, быстрая итерация и работа с неструктурированными или полуструктурированными данными.

3. **Какие операции в MongoDB оказались сложнее/проще по сравнению с SQL?**  
   Проще: вставка сложных вложенных документов (одна операция вместо нескольких `INSERT`). Сложнее: агрегация с `$unwind` и `$lookup` требует большего количества этапов и понимания пайплайна, в то время как SQL-запрос с `JOIN` и `GROUP BY` выглядит компактнее и привычнее.

4. **Что такое `$unwind` и зачем он нужен?**  
   `$unwind` – оператор агрегации, который деконструирует поле массива в входных документах, создавая отдельный документ для каждого элемента массива.
